# 오늘 매수 후보·발굴 신뢰성 점검

운영 화면 관찰: 2026-09-15 16:08~16:16 KST. 코드 수정 마무리: 2026-09-16.
수정·검증 완료 후 사용자가 9/16 커밋·푸시를 요청했다. main 푸시로 자동 배포가 실행되며, 아래 운영 관찰값은 배포 전 기록이다.

## 수정

1. **캐시·DB 복원 추천의 거래정지 게이트 누락**: 계산할 때만 제외하던 종목을 응답 시에도 `StockStatusService.isActive`로 제외한다. 오늘 후보와 5개 발굴 트랙에 적용. 기존 초기 동기화 전 fail-open 의미는 유지한다. 공유 목록 자체는 제거/수정하지 않는다.
2. **조회 실패를 후보 없음으로 표시**: 사용 가능한 결과가 없는 실패 응답은 `dataAvailable=false`, `success=false`로 표시한다. 오늘 탭은 관망 문구 대신 조회 실패를 표시하고 발굴 보드는 트랙 실패를 조용히 생략하지 않는다. 정상적으로 계산된 빈 목록은 여전히 정상 빈 결과다. 이전 캐시가 있으면 기존 폴백은 유지한다.
3. **자동 갱신 누락**: 기존 60초 폴링과 화면 복귀 갱신에 실제 오늘 후보·발굴 보드 조회를 연결한다. 자식 컴포넌트가 이미 로딩 중이면 중복 요청을 하지 않는다.
4. **입력 부족 시 과거 추천 재발행**: 빈 계산 결과를 과거 목록으로 대체해 오늘 시각의 스냅샷과 시그널로 저장하던 경로를 제거한다. 입력 부족은 경고 로그와 함께 저장을 생략하며 기존 DB 행·시각은 보존한다. 정상적인 후보 0건도 기존처럼 기록하지 않는다.

점수 산식, 매수 임계, 수급 캡, 과열 페널티, NXT/KRX 시간 구분과 주문 경로는 변경하지 않았다.

## 재현과 검증

- 캐시 6경로·DB 복원의 거래정지 제외, 실패 응답 구분, 발굴 트랙 실패 전파, 화면 실패 표시와 실제 갱신 호출을 회귀 테스트로 검증했다. 수정 전 실패를 확인했다.
- 과거 추천 재발행 가드는 입력 부족(0/3/9종목)에서도 기록을 생략하도록 기존 기대값을 수정했고, 구현 수정 전 2건 실패를 확인했다. 조회 폴백을 유지하는 것과 새 시그널을 발행하는 것은 구분한다.
- 프론트 전체: 39개 파일, 411건 통과(9/15). 이후 프론트 추가 변경 없음.
- 최종 백엔드 전체: `gradlew test` 성공(9/16, 7분 22초). 242개 XML 테스트 스위트, 1,260건, 실패·오류·건너뜀 모두 0. 프론트 프로덕션 빌드도 성공했다. 종료 정리 중 스케줄러/실행기 대기 시간 초과 경고가 있었으나 최종 종료 코드는 0이었다. 별도 Docker 기반 `migrationTest`는 실행하지 않았다(스키마 변경 없음).
- 최종 `git diff --check` 통과. 아래 테스트 결과는 로컬 검증이며 자동 배포 성공이나 배포 후 운영 검증을 뜻하지 않는다.

## 후속 검증 사항

- 이번 배포 후 캐시가 있는 상태에서 거래정지 동기화 → 응답 제외, 소스 실패 → 실패 표시, 화면을 계속 열어 둔 상태의 실제 갱신을 운영에서 확인할 것.
- 입력 오류를 내부에서 삼키는 개별 채점 경로까지 모두 가용성 판정으로 묶은 것은 아니다. 이번 `dataAvailable`은 외부 조회 실패/폴백 부재를 구분한다.
- 오래된 캐시의 시각은 남지만 realtime 플래그는 거래 시간 여부에 의존하는 기존 경로가 있다. 데이터 신선도를 별도 필드로 제공하는 후속 검토가 필요하다.
- 가격·종목명 결측의 수집/캐시 상태를 운영에서 추적하고, 산식 변경 후 표본을 분리해 비용 포함 성과와 독립 거래일 수를 검증할 것. 점수 기준을 낮추거나 표본 부족을 숨기는 방식으로 해결하지 않는다.
