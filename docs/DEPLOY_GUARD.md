## 화면만 바뀐 푸시는 백엔드를 재시작하지 않게 (설계안만 — 구현 안 함)

- **판정 기준은 '서버에 떠 있는 커밋 ↔ main 끝' 사이의 변경**이어야 한다. 이번 푸시의 `before..after` 로 보면 보류·실패로 쌓인 백엔드 변경을 놓친다. `preflight` 가 이미 서버 라벨을 읽으므로 거기서 `git diff --name-only <서버 커밋>..<main 끝>` 을 계산한다(checkout 은 `fetch-depth: 0`, 서버 커밋이 이력에 없으면 백엔드 변경으로 본다).
- 변경이 전부 `frontend/**`·`docs/**`·`*.md` 이면 `backend_changed=false`. 그때 배포 잡은 dist 전송·nginx 재바인드만 하고 백엔드·파이썬 이미지 빌드와 `--force-recreate` 를 건너뛴다. 장중 가드도 이 경우엔 적용할 필요가 없다(백엔드가 재시작하지 않는다) — 다만 nginx 재시작이 짧게 끊기므로 판단은 사용자 몫이다.
- **'Verify deployed revision' 과 맞추기**: 백엔드 라벨은 그대로 옛 커밋이므로 `github.sha` 와 비교하면 실패한다. 두 가지를 나눠 확인한다 — ① 백엔드 라벨 = `preflight` 가 읽은 서버 커밋(바뀌지 않았어야 한다) ② 화면 커밋 = `github.sha` — 빌드 때 `frontend/dist/revision.txt` 에 커밋을 써서 배포 뒤 `curl https://…/revision.txt` 로 대조.
- 위험: `frontend/` 가 아직 배포되지 않은 새 API 를 부르는 경우 — 판정이 백엔드 변경을 놓치면 화면이 깨진다. 그래서 경로 목록은 '허용 목록'(이것만 바뀌면 생략)으로 두고, 모르는 경로는 백엔드 변경으로 본다.
