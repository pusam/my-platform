# 주식 플랫폼 핵심 경로 점검 — 2026-09-17

기준 커밋: `d00eb7048105e10c0e34632e688cdf254ba75c54`.

사용자 요청: 주식 기능 전반 점검 및 Opus에 전달할 수정 프롬프트 작성. 이번 작업은 점검과 문서 작성이다. 운영 코드·산식·DB·주문·배포는 변경하지 않았다.

## 확인 범위와 검증 한계

시세 캐시/외부 소스 폴백, 종합추천·발굴의 점수/상태 필터, 재무 소비자의 미래 행 필터, 결론카드·체크리스트, 시그널 D+3 교정 평가, 실전 주문·분할매도·일일손실 집계, Python 국면/차트 분석, URL 권한 및 배포 설정의 핵심 경로를 읽었다. 전체 파일을 한 줄씩 전수 검토한 결과는 아니다.

| 검증 | 이번 실행 결과 |
|---|---|
| 프론트 전체 Vitest | 39개 파일, **420건 통과** |
| 프론트 Vite 배포용 빌드 | **성공**, PWA 생성 완료 |

| 운영 화면·운영 DB·외부 API·실제 주문 | **이번 점검에서 검증하지 않음** |

프론트는 권한 제한을 벗어나 테스트/빌드를 실행했다. Python은 기존 `.venv`의 실행기 경로가 깨져 있어 번들 Python 3.12와 기존 `.venv/Lib/site-packages`를 사용했다. 기존 백엔드 XML 결과를 이번 통과 결과로 계산하지 않았다.

아래 문제는 **현재 소스의 호출 흐름으로 확인한 결함/잠재 결함**이다. 운영 사고 발생 건수를 실측한 결과나 새 실패 테스트를 실행한 결과는 아니다. Opus 작업에서 실제 서비스 경로를 타는 재현 테스트부터 작성해야 한다.

## 수정 후보

### F1 — P1: 스캘핑 1차 분할익절은 체결 확인을 건너뛴다

- 근거: `AutoTradingBotService.java:2272` 부근에서 1차 익절 주문 전에 `halfSold=true`를 영속화한다. `executeScalpingSell`의 **2352행**은 `!isPartialSell && isSellConfirmedShort(...)`라 분할익절이면 체결 조회/기록 정정을 호출하지 않는다. 2403행의 롤백은 주문 예외에만 동작한다.
- 연결: `RealTradeService.sell`은 주문 접수 성공 직후 요청 수량으로 SELL 이력과 손익을 저장한다(`RealTradeService.java:520` 부근). `VirtualTradeHistoryRepository.java:90`의 일일손실 집계는 SELL의 `profitLoss`를 합산하며 체결 상태 필터가 없다.
- 재현 입력: 보유 10주 → 1차 익절 5주 주문 → KIS 접수 성공(`rt_cd=0`, 주문번호 존재), 실제 체결 0주 또는 2주.
- 현재 결과: 체결 조회 없이 `halfSold=true`와 5주 매도 이력/이익이 남는다. 0주 체결이어도 1차 익절은 완료로 취급되어 다음 평가에서 같은 분기를 건너뛴다. 미실현 이익이 손실 브레이커 입력을 상쇄할 수 있다.
- 수정 방향: 분할익절도 체결 확인 대상에 넣고, 목표 분할 수량과 실제 체결 누계를 구분한다. **접수된 기존 주문이 살아 있는데 `halfSold=false`만 되돌려 새 주문을 반복하는 수정은 금지**. 주문번호와 미체결 상태를 추적해 기존 주문과 후속 주문을 구별해야 한다. 취소/정정 주문 API는 이번 수정에 임의로 추가하지 않는다.
- 검증: NONE/PARTIAL/FULL/UNKNOWN, 다음 틱·재시작, 기존 미체결 주문의 늦은 체결, 이력·손익·알림, VIRTUAL 경로. 기존 UNKNOWN 정책은 AGENTS의 명시적 불변식이므로 별도 정책 변경 없이 보존한다.

### F2 — P1: D+3 당일 장 마감 전 평가가 확정값으로 저장될 수 있다

- 근거: `SignalD3EvaluationService.java:167–185`는 날짜만 비교해 `D+3 == today`를 평가 대상으로 포함한다. `SignalOutcomeController.java:187–192`의 ADMIN 백필은 시간 확인 없이 `run()`을 호출한다. 기동 따라잡기의 정규장 가드(146행)는 장전에는 통과한다.

- 검증: 장전, 정규장, 마감 경계, 장후, 주말·연휴, D+3 전날/당일/다음날, dryRun/force, 저장 호출 유무. NXT 표시 시간과 KRX 종료 기준을 하나로 합치지 않는다.

## 의도된 정책과 미검증 사항

- 추천의 수급 캡·리스크 raw 차감·유효 카테고리 수·거래정지 응답 필터, 재무 미래 행 필터 및 성장률 writer의 필터를 주요 소비 경로에서 확인했다. 이것은 운영 데이터가 정상이라는 실측 보증이 아니다.
- `currentKospiChannel()` 소비자는 시그널 기록 경로 하나임을 확인했다. 차트 타이밍은 관찰용이며 추천·봇의 실전 성과로 승격하지 않는다.
- **V59 교정값을 신뢰도 게이트로 자동 전환하지 않는다.** 현재 게이트가 구 평가값을 읽는 것은 명시된 전환 대기 정책이다. F2 수정·실제 비교표 확인 뒤 별도 전환 판단이 필요하다.
- REAL 가용현금의 `nxdy_excc_amt` 사용은 기존 미검증 항목이다. 이번에 실전 주문을 넣어 조사하지 않았으며 대체 필드를 추측해 수정하면 안 된다.
- 재시작 잔고 대조의 경고 전용 정책, 매도 UNKNOWN 처리, 일일손실 브레이커의 신규진입만 차단하는 정책을 ‘일괄 안전화’ 명목으로 바꾸면 안 된다.
- `@EnableMethodSecurity`가 없고 URL 규칙이 실제 권한을 담당한다. 봇/REAL/관제실/D3의 ADMIN URL 규칙을 확인했다. 인증 전체의 침투 테스트를 수행한 것은 아니다.
- 운영 재무 충전율, 데이터 신선도, 토큰 갱신, 실전 체결 필드 및 교정 전후 성적은 운영 자료가 필요하다. 이번 결과만으로 ‘추천대로 매수해도 된다’거나 ‘실전 자동매매가 안전하다’는 결론을 내릴 수 없다.
