#### §4b.3

- 모닝브리핑(07:30) 후행 워밍: BUY 컷(55) 이상 **상한 5종목** — Gemini quota 가드. 근거 없이 늘리지 말 것. ⚠ **이 크론을 포함한 `StockAlertScheduler` 8개(07:30 브리핑·08:30 장전·16:45 장마감·관심종목 5분·종합 10분·월 어닝서프라이즈·공매도 18:30/19:00)는 `alert.scheduler.enabled`(기본 **false**) 뒤에 있고, 2026-01-29 게이트 도입 후 2026-09-04 까지 prod 에서 한 번도 안 돌았다** — `ALERT_SCHEDULER_ENABLED` 가 compose 에 배선돼 있지 않았고 스킵 로그가 DEBUG 라 무음이었다. 지금은 compose `environment:` 에 `${ALERT_SCHEDULER_ENABLED:-true}` 로 배선 + 부팅 시 꺼져 있으면 WARN 1회. **단 복합 조건 알림(10분)은 자기 플래그 `alert.composite.enabled`(기본 false) 로 따로 꺼 뒀다** — 켠 첫날 10:00 tick 에 36건, 10:10 에 12건이 시그널 채널로 나갔다(임계 기관 +8억·등락 +4% 가 한 번도 실측 보정된 적 없음, 60분 쿨다운은 같은 종목 반복만 막음). **임계를 실측으로 다시 잡기 전에 `ALERT_COMPOSITE_ENABLED=true` 로 켜지 말 것** — 켜면 tick 마다 수십 통이다. **KIS 를 부르는 크론은 초 필드 `:00` 을 피한다** — 잔고 모니터(급락 2분·공시 5분)와 워머가 `:00` 에 몰려 있고 KIS 는 계좌당 초당 건수를 자른다(EGW00215). 관심종목 5분 크론이 처음 돈 날(2026-09-04) 10:30:00 시세 1건이 잔고 조회를 밀어냈다 → `30 */5` 로 옮김(테스트 고정). 잔고 단일 비행은 잔고끼리의 충돌만 막지 시세와의 충돌은 못 막는다. **새 `…enabled:false` 게이트를 만들면 compose 배선과 부팅 WARN 을 같이 둘 것** — 기본 false + DEBUG 스킵은 "조용히 안 도는" 조합이다(§4c). **일괄 워밍(08:00 `CatalystWarmingService`, P2-CAT3) 대상 = 관심 > 보유 > 발굴 5트랙, 전체 40 컷** — 오늘 탭/보드/이력은 일캐시 **read-only**(리스트 화면에서 classify 트리거 금지). ⚠ "오늘 매수후보(getTop5)" 그룹은 2026-08-20 넣었다가 **08-21 원복** — 08:00 엔 재계산이 없어(캐시 무효화뿐, 장전이라 백그라운드 계산도 미트리거) getTop5 가 전일 20:05 스냅샷 = 07:30 브리핑 워밍과 동일 집합이라 실익 0 + 발굴 몫만 잠식. **다시 넣지 말 것** — 오늘 후보 배지 공백의 진짜 해법은 11:30 첫 스냅샷 이후 워밍(AUDIT R11, 신규 크론 판단 필요).

#### §4b.7

- **Gemini quota — 무료 티어 rate 제한(2026-07-01 해소)**: 모델 **`gemini-2.5-flash-lite`**(2.0-flash 종료, 무료 ≈15 RPM, URL 은 `${GEMINI_API_URL}` 로 오버라이드). `GeminiService.RateLimiter`(synchronized `acquire()` + 슬롯 예약)로 **전역 직렬화**, 간격 **4.5초**(≤~13 RPM, 15 미만). 이전 `enforceRateLimit` 은 volatile check-then-act(비원자적)라 동시 호출자(재료·AI전략·StockDetail 등) 버스트가 통과 → 429 였음 — **이 비원자 방식/2초 간격으로 되돌리지 말 것.** 503(구글 과부하)은 재시도 자동복구, 429는 rate 제한으로 방어 → 재료+AI전략 둘 다 정상. **후속(백로그)**: 배치 프롬프트(N종목 1콜=RPM 실질 감축, 무료 티어 최선책). ⚠ 프롬프트 프리픽스 캐싱은 **토큰 비용만↓**(RPM 무관)이라 429 완화엔 무효 — RPM 은 rate 제한/호출수 감축으로만. **⚠ 지금 묶는 한도는 하루 20회다(2026-10-06 확정, 429 본문 `GenerateRequestsPerDayPerProjectPerModel-FreeTier · 한도 20`)** — 태평양 자정(한국 16시, 서머타임이 끝나면 17시)에 초기화된다. **소비자 우선순위(재료>AI전략)를 2026-10-07 에 넣었다**: 저우선(AI 전략 코멘트·테마 — 10/6 부터 점수와 무관한 표시용, **AI 주식 분석 코멘트도 2026-10-19 부터** — TOP PICK 문구에만 쓰이는데 워머가 저녁에도 매시간 다시 돌려(회차당 최대 6회) 16시에 열린 새 창을 아침 재료 분류 전에 써 버렸다, `GeminiService.lowPriorityCallAllowed`)은 그 창의 호출이 `gemini.quota.daily-requests`(20) − `gemini.quota.high-priority-reserve`(12) = **8회 미만일 때만** 부르고(`GeminiService.lowPriorityAllowed`, 창은 `quotaDay` = 태평양 날짜), 나머지 12회는 재료 분류(07:30·08:00)·종목 상세 AI 분석 몫이다. 예전엔 16~19시 AI 전략 회차가 새 창을 먼저 써서 다음 날 아침 재료 분류가 429 를 맞았다. 창 집계는 실제 HTTP 시도마다(재시도 포함, 보수적) · **프로세스 메모리라 재시작하면 0 부터**(배포 날은 저우선이 예산보다 조금 더 쓸 수 있다) · 소진은 창마다 INFO 한 줄. 한도를 0 이하로 두면 끈다(종전 동작). 기존 `gemini.usage.daily-limit`(500, 한국 자정 리셋, 80·90% 텔레그램)은 진짜 한도와 무관한 옛 값이다 — 알림이 울리지 않는다고 여유가 있는 게 아니다(`GeminiQuotaBudgetTest`).
