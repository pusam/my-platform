# §4c 날짜별 점검 기록 — 이름표는 데이터가 가진 날짜·정의로(2026-10-02 화면 점검)

> 2026-11-11 에 옛 `CLAUDE.md` 에서 글자 그대로 옮긴 경위 원문이다. **지킬 규칙은 `CLAUDE.md` §4c 의 규칙 줄에 있다** — 이 문서는 '왜'를 위한 것이다.
> 번호(예: `§4c.13`)는 옛 `CLAUDE.md` 의 절과 그 절 안 항목 순서다(하위 항목은 `§7.8-2`). 문단 안의 '위·아래 항목'은 이 순서를 가리킨다 — 전체 순서표는 `docs/rules/README.md`.
> 번호 제목 바로 아래의 '정정(날짜): …' 줄은 옮긴 뒤 붙인 것이다(문단은 손대지 않았다).
> 사실이 바뀌면 문단을 고치거나 정정 줄을 붙이고, `CLAUDE.md` 의 같은 번호 규칙 줄도 같이 고친다. `AGENTS.md` 는 `CLAUDE.md` 의 사본이고, 이 문서는 두 쪽이 같이 읽는다.

#### §4c.42

- **이름표는 데이터가 가진 날짜·정의로(2026-10-02 화면 점검)** — 값은 맞는데 이름표가 틀린 것들: ① 시장 탭 매매 동향 머리말이 브라우저 시계로 "10.02 11:24 (잠정)"을 붙였는데 데이터는 10/1 장 마감 확정치였다 → 응답의 `tradeDate` 로 "MM.DD 장 마감 집계" (`utils/marketDataLabels.tradeDataLabel`). ② 매매 동향 표·연속 매수 카드의 "현재가"는 저장된 그날 종가였다 — 오늘 탭·종목 상세의 실시간 시세와 값이 갈려 보였다(§1 이 막으려던 불일치) → "종가(MM.DD)". ③ 매매 내역 사유는 `TradeReasonLabels` 단일 출처 — 예전 두 벌의 switch 에 봇 사유 8가지(스윙·종가 매수, 정규장·스캘핑·갭 청산 등)가 없어 봇 매매가 **"수동"**으로 보였다. 모르는 코드는 코드 그대로(수동으로 단정 금지). ④ 주간 매매 리포트는 거래 0건 주에 Gemini 를 부르지 않는다(`TradingDiaryService.noTradeReport`) — 예전엔 "다음 주엔 반드시 1회 이상 매매" 같은 조언을 지어냈다. ⑤ 해외 시세 장 상태가 응답에 없으면 null(예전 기본값 "CLOSED" 로 장중에도 "장마감"). ⑥ 시장 타이밍 원자재 카드 — 유가는 `pricePerBarrel`(예전 `price` 로 "$-"), 환율은 감싸지 않은 DTO 라 항목이 빠졌다. ⑦ 실적 스크리너 "129,414개 종목"은 재무 테이블 누적 행 수였다 → "누적 N건". ⑧ 홈 '시장 HUD'는 ADR null 을 응답 수신 여부로 가른다 — 받았으면 'ADR 판단 보류', 못 받았을 때만 '데이터 없음 — 불러오지 못했습니다'(예전엔 판단 보류도 '불러오지 못했다'로 보였다, `useMarketStatus.getMarketStatus`). 회귀 `TradeReasonLabelsTest`·`TradingDiaryNoTradeReportTest`·`GlobalFuturesMarketStateTest`·프론트 `marketDataLabels.test.js`·`useMarketStatus.test.js`.
